Attempt 2 dispatch receipt reaches `FINALIZED`; its completion tombstone winner is `completion` and its dispatch identity matches the retry receipt.

## Production defects found and repaired

The E2E exposed four production defects. The user explicitly authorized production repair if the accumulated `.12c.1` through `.12c.2.4` chain remained insufficient.

- Windows Job liveness read `ctypes.get_last_error()`, which returned zero for these Win32 calls. The probe now reads `kernel32.GetLastError()` so authoritative `ERROR_FILE_NOT_FOUND` can be distinguished from permission/API uncertainty. DEAD still requires exact DEAD supervisor and Worker identities; all other evidence gaps remain UNKNOWN.
- Owner-loss `DISPATCH_FAILED` used event lease epoch zero and an empty actor, producing evidence rejected by `StateProvider`. The atomic transition now binds the canonical PM holder and uses a schema-valid event epoch while preserving legal canonical `pm_control.lease_epoch == 0`.
- A fast attempt 2 Worker could advance its dispatch receipt beyond `WORKER_STARTED` before retry lifecycle wiring read it. The guard now accepts any forward phase at or beyond `WORKER_STARTED` and still rejects earlier phases.
- Recovery replay rebuilt the existing event with the current clock, violating byte-exact replay. Replays now bind transition time to the persisted recovery event `occurred_at`; new recoveries continue to use the current clock.

All phase writes and retry execution remain outside the control-plane state lock. The second liveness check and `DISPATCH_FAILED` remain inside one state-lock critical section; the transition helper does not re-enter public `apply_transition()`.
