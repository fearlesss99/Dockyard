## Root Cause

The write side (`control_plane_transition.py` `_mutate_task()`) correctly writes
`cancelled_at` into `timestamps` for `BLOCKER_CANCELLED` and `TASK_CANCELLED`,
and `superseded_at` for `TASK_SUPERSEDED`.  However, `StateProvider`'s read side
only recognised the original nine timestamp fields, rejecting the two terminal
keys as forbidden.  This made it impossible to read canonical state via
`StateProvider.snapshot()` after cancellation or supersession.

## Compatibility Strategy

- The original nine timestamp keys remain **required** (`_validate_missing_keys`
  still checks them).
- `cancelled_at` and `superseded_at` are **allowed but optional** — their keys
  may be absent from `timestamps` for non-terminal states.
- When present, they must be `str` or `null`; non-string types are rejected.
- When absent, the corresponding `TaskTimestamps` dataclass attribute defaults
  to `None` via Python default-kwarg values.
- Unknown/extra timestamp keys remain rejected by `_validate_extra_keys`.
- Backward compatibility: all existing nine-key fixtures continue to work
  without modification.
