## Python control-plane matrix

The committed matrix contains 17 scenarios and covers:

- Host, Origin, CSRF, Bearer token, route, payload, and resource substitution;
- pairing-code replay, stolen-token/device mismatch, and device revocation;
- path traversal and same-path repository replacement;
- stale revision, attempt, dispatch, generation, event, provider, and model;
- concurrent plan creation and duplicate retry with one canonical winner;
- terminate and retry zero-write rejection before cancellation callbacks;
- attempt 4 rejection before reservation, lease, dispatch, or outbox writes;
- SSE replay, ahead-cursor rejection, and credential-free event payloads;
- malicious `__str__`/`__repr__` values without invoking attacker code;
- malicious provider stdout/stderr/prompt text producing only the typed
  `RETRY_FAILED` boundary and the private `worker_failed` finalizer
  classification; and
- soft project removal replay without deleting or rewriting the Git repository.

The full Python file ran 17 scenarios: 16 passed and one obsolete expectation
still treated the now-wired retry owner as HTTP 403.  That assertion was updated
to the actual typed zero-write `409 COMMAND_OWNER_UNAVAILABLE` boundary and the
affected test then passed 1/1.  The resulting committed matrix therefore has
passing evidence for all 17 scenarios without rerunning the other 16 already
green cases.

The owner-loss evidence matrix is inherited unchanged from
`978656b5456b5804b071ab16fe2a02392bfdb29b`: ALIVE is zero-write, UNKNOWN is
fail-closed, only DEAD can enter recovery, two recoverers share one attempt-2
identity, and failed attempt 3 never reserves attempt 4.  Its six directed tests
were already green and were not duplicated here.
