## Current / Target Boundary

### Current (implemented and E2E-verified)

- Dispatch cycle: snapshot → acquire → TASK_DISPATCHED → heartbeat → run_worker → DISPATCH_ACKNOWLEDGED → decode → DELIVERY_SUBMITTED → stop heartbeat → release → result
- Delivery remediation: audit fail → DELIVERY_RETURNED → TASK_REQUEUED
- Blocked audit escalation: TASK_BLOCKED → EscalationService
- Escalated redispatch: BLOCKER_RESOLVED → single run_dispatch_cycle
- Integration failure: INTEGRATION_FAILED recording
- Expert rescope: BLOCKER_RESCOPED → draft
- Expert cancellation: BLOCKER_CANCELLED
- Quiescent task cancellation: TASK_CANCELLED (no active dispatch)
- Quiescent task supersession: TASK_SUPERSEDED (no active dispatch)
- StateProvider read-only snapshot: 25-field TaskEntry with `superseded_by`
- Nine scenario E2E test suites

### Explicitly Target (not yet implemented)

- Active-dispatch cancellation (TASK_CANCELLED with running Worker)
- Active-dispatch supersession (TASK_SUPERSEDED with running Worker)
- Codex decoder (WorkerOutput decode for Codex provider)
- Codex rate-limit classification
- Retry-loop fault recovery
- TC-13.20 HTML Dashboard
- Interface #22 WorkflowOrchestrator retry/replay/codex paths

TC-13.19 Current _only_ means "the E2E evidence program for all currently
implemented capabilities is complete."  It does NOT claim that all future
Orchestrator functionality is implemented.
